\section{Paraphrasing using phrase-based machine translation}
\label{moses}
%\addcontentsline{toc}{chapter}{moses}

In this and the following sections,\footnote{This section is based on the article \citep{barancikova:itat2014}, which is a joint work with Aleš Tamchyna. Aleš was responsible for training and tuning Moses, while my contributions included data preparation, paraphrasing and experimental evaluation.} we investigate targeted paraphrasing using machine translation techniques. Since both machine translation and paraphrasing aim to preserve meaning, differing primarily in whether the output language changes or remains the same, it is natural to consider adapting translation systems for monolingual paraphrasing.

Machine translation benefits from a well-established set of tools and resources, whereas dedicated paraphrasing systems remain comparatively scarce. This motivates the following research question: how can existing machine translation frameworks be adapted to enable targeted paraphrasing within a single language? We address this question by exploring modifications required to generate Czech targeted paraphrases.

This section focuses on phrase-based machine translation using Moses, while the following section examines the rule-based system Treex. Moses \citep{moses} was one of the most widely used open-source frameworks for statistical machine translation (SMT) for more than a decade until the rise of neural machine translation (NMT). The introduction of the Transformer \citep{attention} architecture and pre-trained models has led to substantial improvements in translation quality and made NMT the prevailing approach for machine translation.

Despite NMT rendering SMT obsolete in recent years, we continue to utilize Moses. The reason is partly historical: our research began prior to the widespread adoption of NMT, situating our experiments within the context of SMT's prevailing technologies at the time.  More importantly, phrase-based SMT provides a transparent log-linear modeling framework in which individual features can be explicitly inspected and controlled. This level of interpretability is particularly useful for targeted paraphrasing, where we aim to manipulate specific aspects of the generated output. In contrast, neural models typically operate as black-box systems with limited direct control over intermediate decisions.

In our approach, Moses is repurposed as a monolingual translation system that generates paraphrases of reference sentences. The original reference sentence is treated as the source, and the system produces alternative Czech formulations using paraphrase phrase tables. During decoding, an additional feature guides the system to generate paraphrases that maximize lexical overlap with a given translation hypothesis, thereby enabling targeted paraphrasing.

This chapter first introduces necessary components of phrase-based SMT, then describes our adaptations for monolingual paraphrasing, and finally evaluates their effectiveness on the WMT12 dataset \citep{wmt12}.

\subsection{Moses overview}
The Moses system generates translations using statistical models. The translation process involves the following phases: creating language and translation models, parameter tuning, and the decoding process. 

The language model is responsible for ensuring syntactic correctness and grammatical integrity of the translated sentence. The translation model (also referred to as a phrase table) provides all possible translations for a given word or phrase. 

Following the construction of the models, the next phase consists of parameter tuning. During this step, the model weights are optimized to maximize translation quality on a development set. Various optimization techniques, such as minimum error rate training (MERT) or~maximum likelihood estimation, are applied to fine-tune the statistical models.

During decoding, the final phase, a beam search algorithm is employed to~efficiently find the best translation among potentially numerous candidates generated from a source sentence.  More specifically, an input sentence is divided into smaller units, words and phrases, and they are translated largely independently. The algorithm keeps only a limited number of hypotheses (partial translations), focusing only on the most promising ones based on their cumulative scores. These scores are computed as a combination of different model scores and their corresponding weights, which are learned during the training process.

\subsubsection{Language Model}
\label{sect-LanguageModel}
The language model (LM) is essential to ensure that translations are not only grammatically correct but also fluent in the target language. It plays an important role~in resolving ambiguities and ensuring the contextual integrity of the translated text. 

To adapt Moses to produce paraphrases, the construction of a language model does not require modifications, since it is based solely on monolingual data. We created our language model using the SRILM toolkit \citep{srilm} with data from the Czech component of the Czech-English parallel corpus CzEng \citep{czeng10:lrec2012}.

\subsubsection{Translation model}
\label{sect-TranslationModel}
The translation model is responsible for generating possible translations of a~source language sentence into a~ target language. This model identifies the most probable translations of individual words or phrases and then combines them to~form complete sentences in the target language. 

Fundamentally, a translation model (or phrase table) is structured as an extensive lookup table. Each entry in this table consists of a source phrase and its corresponding translation. To help the decoder choose the best candidates, each entry includes several additional components:

\begin{itemize}
    \item Feature Scores: These typically include translation probabilities (the likelihood that phrase A translates to phrase B and vice versa) and lexical weights.
    \item Translation Frequencies: The model also tracks the frequencies of these possible translations as observed in the original training corpus.
    \item Phrase Alignment: Optionally, the table may include specific word-level alignments between the phrases in the two languages to show which words correspond to each other.
\end{itemize}

Feature scores, alignment and frequencies are automatically learned by analyzing large parallel datasets using tools such as GIZA++ \citep{gizapp}. It estimates translation probabilities, focusing on how words and phrases in a source language correspond to those in the target language. The effectiveness of the phrase table depends on the quality and volume of the bilingual corpora used for training. 


\subsection{Paraphrase tables for Moses}
\label{sect-PhraseModel}
To adapt Moses for monolingual paraphrasing, we need data consisting of sentence pairs in the same language that express equivalent meanings, i.e., paraphrases. Such data would play a role analogous to parallel corpora in standard machine translation. However, large-scale Czech datasets of this kind, containing aligned paraphrastic sentence pairs, are not available.

In view of this, we adopt an alternative approach to constructing the translation model. Instead of relying on sentence-aligned paraphrase data, we utilize existing Czech paraphrase tables, which provide pairs of semantically related expressions. While these resources do not constitute parallel corpora in the traditional bilingual sense, they can be interpreted as a form of alignment at the phrase level.

We construct two complementary phrase tables: an enhanced version of the \cmpt table and a \owpt derived from lexical resources and the CzEng corpus.

\subsubsection{\enhanedmeteor tables}

The \enhanedmeteor table is derived from the \cmpt (as described in \Cref{meteori}). Each paraphrase pair has a pivot score that we repurpose as a~feature in our phrase table. However, our analysis in Section \nameref{filtering-section} in~the Appendix shows that this score performs worse than random selection. To compensate for this limitation, we introduce additional feature scores based on distributional semantics \citep{miller-91}. This approach is based on the hypothesis that words or phrases that occur in similar contexts tend to have similar meanings. This principle is often summarized by the aphorism ``You shall know a word by the company it keeps'' \citep{firth1957}. 

Distributional similarity has previously been used to re-rank automatically extracted paraphrases, notably by \cite{chan-etal-2011-reranking} and \cite{ppdb}, who applied it to paraphrases obtained from parallel bilingual corpora. Distributional semantics is efficient in eliminating incorrect paraphrases generated by lexical ambiguity, as such words rarely occur in similar contexts. Given that \cmpt was also constructed automatically from parallel corpora (as detailed in \cref{meteori}), it is reasonable to incorporate distributional similarity scores as additional features into our translation model.

To compute these similarity scores, we extract contextual occurrences of paraphrases from \cmpt in~the Czech National Corpus \citep{SYN2010}. Contexts are defined as words occurring within a fixed window around the target phrase. The window size parameter specifies how many words are considered on each side; for example, a window size of~1 includes only immediately adjacent words, whereas a window size of~3 includes three words to the left and three words to the right.

For each paraphrase pair, we represent the contexts in which the phrases occur as context-frequency vectors and compute their cosine similarity. This provides a graded estimate of how similar the contexts of the two phrases are, helping us distinguish genuine paraphrases from false pairs.  A worked example of the cosine similarity computation on a toy corpus is provided in the Appendix \nameref{app:distributional}.

Using this procedure, we add six contextual similarity features to each paraphrase pair in \cmpt. These scores vary according to (i) the context window size and (ii) whether word order within the window is preserved. We use window sizes of 1–3 to capture both local and slightly broader contextual information, while distinguishing between ordered and unordered contexts allows us to model both strict syntactic patterns and more flexible co-occurrence signals. Together with the original pivot score, the resulting \enhanedmeteor phrase table contains the following seven features: 

\begin{enumerate}
\item \textbf{pivot score}: the score adopted from \cmpt
\item \textbf{context similarity (window size 1, ordered)},
\item \textbf{context similarity (window size 2, ordered)},
\item \textbf{context similarity (window size 3, ordered)},
\item \textbf{context similarity (window size 1, unordered)},
\item \textbf{context similarity (window size 2, unordered)},
\item \textbf{context similarity (window size 3, unordered)}.
\end{enumerate}


\subsubsection{\owpt}

Our second phrase table is a one-word paraphrase table created from CzEng 1.0, a sentence-parallel Czech-English  corpus \citep{czeng10:lrec2012}. As a preliminary step, we created a~candidate set by compiling all words from the Czech part of CzEng. We set a frequency threshold to at least five occurrences in the corpus to filter out rare words and potential typographical errors. This set was further expanded with words from the WMT12 hypotheses and references, totaling 447,540 words.  Morphological analysis was performed using the Morče tool \citep{morce:2007} to obtain lemmas and POS tags.

The \owpt  includes word pairs $(x, y)$ from the list of candidate words satisfying any of the following:

\begin{itemize}
\item $x = y$ (identity, because not every word should be paraphrased);
\item $x, y$ share the same lemma (inflectional variants, because a word can be in a different inflected form in a paraphrased sentence);
\item lemmas of $ x,y $ are paraphrases in \wordnet or \fm.
\end{itemize}

% 1,121,988
This phrase table contains over 1.1 million pairs. For each pair of words $ x,y $, we add five feature scores that primarily function as binary indicators specifying whether a given relationship holds between the two words (e.g., identity, shared lemma, or membership in an external lexical resource). Rather than representing probabilities, these features simply activate specific signals that can be weighted during model tuning. For each pair of words $ x,y $, we add the following five feature scores:

\begin{itemize}
\item \textbf{identity:} $ e^1 $ if  $ x = y $, $e^0$ otherwise,
\item \textbf{same lemmas:} $ e^1$ if  $ x $ and $ y $ have the same lemma, $e^0$ otherwise,
\item \textbf{WordNet:} $e^1$ if  lemmas of $ x $ and $ y $ are paraphrases according to the Czech WordNet, $e^0$ otherwise,
\item \textbf{\fm:} $ e^1$ if  lemmas of $ x $ and $ y $ are paraphrases according to \fm, $e^0$ otherwise,
\item \textbf{POS similarity:} $ e^{\frac{1}{a+1}}$, where $ a $ represents the minimal Hamming distance between the positional morphological tags of the two words, i.e., the number of positions at which the tags differ. We use a positional tagset in which each position encodes a specific morphological category (such as part of speech, gender, number, or case), rather than a single coarse POS label. For example, a tag such as \texttt{NNMS1-----A----} represents a noun (N), masculine (M), singular (S), in nominative case (1), followed by additional morphological features.
\end{itemize}

The \textbf{POS similarity} feature is intended to capture the morphological similarity between candidate paraphrases, reflecting how closely they align in grammatical function and inflectional properties. It should be noted, however, that all tag mismatches are treated uniformly in the Hamming distance. In particular, the absence of a morphological feature (typically marked by ``-'') is treated the same as a mismatch between two explicitly specified values. Linguistically, this may underestimate certain differences, as the absence of a feature can signal a stronger divergence than differing values of the same category. Nevertheless, this simplified formulation allows the feature to be efficiently incorporated into the model.

Since Moses internally operates in log space, these exponential values ($e^1, e^0$) are transformed into 1 and 0 during decoding. This representation allows the features to function as binary activations rather than probabilities, avoiding numerical issues with zero values while allowing the model to learn appropriate weights for each signal.

Taken together, the \enhanedmeteor table and the \owpt aim to balance semantic coverage and lexical control.

\subsection{CoveredReferenceFeature}
\label{sect-CoveredReferenceFeature}

Using  \enhanedmeteor and \owpt as phrase tables, Moses can already generate Czech-to-Czech translations. However, such paraphrasing would be unconstrained, as the system simply produces the most probable output according to the translation model. 

To enable targeted paraphrasing, we introduce a novel feature  into the Moses translation engine that guides the decoder towards outputs with a higher degree of similarity to a given translation hypothesis.

This feature, called \textbf{CoveredReferenceFeature}, measures the lexical overlap between each candidate paraphrase and the evaluated hypothesis. The objective of this feature is to prioritize candidate paraphrases that are closer to the evaluated system output. 

The overlap is defined as the number of words in the candidate paraphrase that also appear in the evaluated hypothesis. This computation is intentionally simple and computationally efficient. More complex overlap measures were avoided, as they would significantly increase the computational cost of beam search.

The integration of this feature into Moses' beam search algorithm, used in the phrase-based decoding phase, requires tracking the feature state. The feature state tracks which words from the evaluated hypothesis have already been covered by the candidate paraphrase. This state tracking is essential for accurate hypothesis recombination, as it allows the beam search algorithm to maintain a comprehensive understanding of which parts of the reference translation have been covered. 

Furthermore, we implement an estimator that predicts the potential of a given phrase to cover additional words from the reference translation. It is defined as the number of reference translation words covered by the given phrase. 

The code for \textbf{CoveredReferenceFeature} was written by Aleš Tamchyna and it is included in the Moses GitHub repository.\footurl{https://github.com/moses-smt/mosesdecoder/} 


\subsection{Additional Features}
\label{sect-OtherFeatures}
In addition to the already mentioned language model (\cref{sect-LanguageModel}), the features of the translation models (\cref{sect-PhraseModel}), and \textbf{CoveredReferenceFeature} (\cref{sect-CoveredReferenceFeature}), the Moses decoder also originally incorporates three additional features that influence hypothesis scoring:

\begin{itemize}
    \item \textbf{Distortion:} This feature measures the cost associated with reordering phrases from their positions in the source sentence to their positions in the translated sentence. A higher distortion cost penalizes more significant rearrangements, encouraging the translation to preserve the original order of the source sentence as much as possible.

    \item \textbf{WordPenalty:} This feature controls the length of the output translation. Typically, it penalizes translations for each word produced, encouraging the model to generate more concise translations. This feature helps to balance the length of the translation, preventing too long or too brief translations.
    
    \item \textbf{PhrasePenalty:} Similar to the \textbf{WordPenalty}, the \textbf{PhrasePenalty} 
    feature is concerned with the number of phrases in the translation. This penalty is applied for each phrase used in the translation, influencing the model to prefer translations with an optimal number of phrases. A low \textbf{PhrasePenalty} (close to 0) means little to no discouragement for using multiple phrases, potentially leading to more detailed, possibly fragmented translations.
\end{itemize}

\subsection{Parameter tuning using MERT}
\label{sect-ParameterTuning}

We use the minimum error rate training (MERT) \citep{mert} to find the optimal weights for our models to minimize the error rate on a development dataset. In the original setting, these validation datasets consist of parallel data: source sentences, and their professional translations. Within the original MT task, MERT learns the weights by iteratively translating each source sentence from the validation dataset, calculating an error metric (such as \bleu) by comparing it to the reference translation, and adjusting the model weights to minimize average error across all candidates until the error rate stops improving significantly.

In the paraphrasing setting, suitable parallel validation data is not readily available. We briefly experimented with Many Czech References dataset \citep{bojar-scratching}, which contains human-created paraphrases of 50 sentences. Despite the high quality of these paraphrases, the dataset is very limited in its size and variability.

Therefore, due to the absence of more suitable datasets, we instead construct a development set from the WMT13 dataset \citep{wmt13}, pairing reference sentences with the highest-ranked system hypothesis according to human evaluation. Although this setup differs from the traditional machine translation setting, it provides a practical approximation for learning model weights that encourage lexical similarity between references and hypotheses.

The learned feature weights (\Cref{table:weights}) provide important insight into the behavior of the system. The \textbf{CoveredReferenceFeature} receives by far the highest weight (0.513), indicating that the optimization process is dominated by the objective of maximizing lexical overlap with the evaluated hypothesis. This behavior is, in fact, consistent with our goal of targeted paraphrasing: we explicitly aim to generate reference variants that are lexically closer to system outputs.

However, the combination of this feature with \bleu-based optimization leads to an unintended consequence. Because \bleu directly rewards n-gram overlap, the \textbf{CoveredReferenceFeature} becomes an extremely strong signal, effectively encouraging the system to reproduce the hypothesis as closely as possible. Instead of guiding paraphrasing in a controlled manner, it maximizes the lexical overlap at all costs.

\textbf{Word Penalty} has the second highest weight (0.291), giving high importance to penalizing overly long outputs. Together with the \textbf{CoveredReferenceFeature}, it creates a trade-off between maximizing lexical overlap and controlling sentence length. In other words, \textbf{CoveredReferenceFeature} pushes Moses to copy the hypothesis, while Word Penalty prevents it from copying too much — but neither enforces grammaticality or meaning. 

In contrast, the \textbf{Language Model} receives a very small weight (0.016), suggesting that grammaticality and fluency contribute little to the optimized objective. As a result, the system frequently generates ungrammatical paraphrases that nevertheless achieve high \bleu scores due to increased lexical overlap.

Similarly, features derived from the paraphrase tables, including the pivot score and distributional similarity measures in the \textbf{\enhanedmeteor} table, receive negligible weights. This indicates that these features do not contribute meaningfully to \bleu optimization, as they capture semantic similarity rather than exact surface overlap. The features of the \textbf{\owpt} have slightly higher weights, particularly POS similarity, but remain marginal compared to the dominant targeting feature.

Overall, these results highlight a fundamental mismatch between the optimization objective and the intended task. While the goal of targeted paraphrasing is to generate grammatical and semantically equivalent variants of the reference sentence, the \bleu-driven optimization instead encourages the system to approximate the hypothesis as closely as possible at the surface level. Consequently, the model behaves more like a guided copying mechanism than a true paraphrasing system, prioritizing lexical overlap over fluency and meaning preservation.

\Fref{visualization} provides a visual overview of our findings. The graphs demonstrate that while paraphrasing via Moses with MERT-learned weights consistently increases \bleu scores, it fails to improve the correlation with human judgment. In fact, it is substantially degraded. Increasing the weights of the language model, intended to improve grammatical accuracy, instead contributed to unpredictability and decreased coherence between \bleu scores and human judgment. 

Importantly, none of the paraphrasing configurations surpasses the baseline correlation obtained using the original, non-paraphrased reference sentences. This contrasts with the simpler paraphrasing approach discussed in \Cref{substitution}, where targeted lexical variation yielded consistent gains.

The observed degradation can be attributed to several interacting factors. First, MERT optimization against \bleu disproportionately rewards lexical overlap, causing the \textbf{CoveredReferenceFeature} to dominate the model. As a consequence, other components—most notably the language model—receive negligible weights. Specifically, the paraphrases generated by the \textbf{Paraphrased} setting, despite achieving a significantly higher \bleu score, were mostly ungrammatical, which negatively affected the correlation of our metric.

Second, manually increasing the weight of the language model paradoxically introduces new complications. This adjustment produces grammatically correct references that, regrettably, tend to have little or no relevance to the original source sentence. This observation indicates that the noise inherent in the automatically constructed paraphrase tables outweighed the corrective capacity of the language model, leading to fluent but semantically disconnected outputs.

Finally, the design of the targeting feature itself contributes to the problem. Operating purely at the word level and ignoring word order or syntactic structure, it permits translations with scrambled structure as long as lexical overlap is maintained. As a result, the feature acts as a strong oracle for word coverage but provides no guarantees with respect to fluency or syntactic adequacy.

These effects are further reflected in the learned feature weights. All features of both translation models---the \owpt and \enhanedmeteor---receive very small weights, with the highest assigned to POS similarity. This indicates that neither the pivot score nor the distributional semantic features are effective in distinguishing valid paraphrases from noise.

\Fref{fig:moses_sentences_example} illustrates these failure modes. While the hypothesis is fluent and semantically appropriate, the paraphrased reference generated under the default setting contains grammatical errors. Increasing the language model weight yields fluent outputs, but at the cost of semantic drift, resulting in references that no longer correspond to the source sentence.

\subsubsection{Monotone decoding}

Given the unsatisfactory results, we experimented with three additional configurations: 

\begin{itemize}
    \item \textbf{Lexical:}  This setting is based on the basic \textbf{Paraphrased} setting, the only difference is utilizing only one translation model -- the \owpt, focusing on lexical substitutions without considering the \enhanedmeteor table. 
    \item \textbf{Lexical \& LM+0.2:} This setting combines the lexical approach with an increment of 0.2 in the language model weight, aiming to enhance grammatical accuracy while maintaining a focus on simple lexical paraphrases.
    \item \textbf{Lexical \& Monotone:}  This configuration applies lexical paraphrasing within a monotone translation framework, i.e., explicitly disabling reordering to address issues related to scrambled word order.
\end{itemize}

This decision proved to be reasonable as the correlation between \bleu scores and human judgment in the \textbf{Lexical} setting showed an improvement of 0.06 compared to the \textbf{Paraphrased} setting. The idea to explore monotone translation 
was motivated by the frequent occurrence of disordered word sequences and misplaced punctuation in the \textbf{Paraphrased} setting. The \textbf{Lexical \& Monotone} setting yielded the best results among all paraphrased hypotheses tested.

Despite these modifications leading to an improved correlation with human judgment, they did not surpass the baseline results. We observed a noticeable improvement in the \bleu score, suggesting a greater overlap between the newly generated references and the hypotheses. Interestingly, this increase was even higher when  monotone decoding was added --- indicating that disabling reordering helped to cover longer n-grams that were previously 
shuffled. 

This suggests that while targeting specific areas of improvement such as lexical choice and sentence structure can yield positive changes, achieving an overall translation quality that exceeds the baseline using Moses remains a challenge. These findings show the complexity of phrase-based machine translation and the difficulty of balancing its individual components to produce paraphrases that are both accurate and grammatical.

\noindent 
In conclusion, we answered the following research questions:
\paragraph{Can a phrase-based SMT system be adapted for targeted monolingual paraphrasing?}
Yes, we demonstrate that Moses, traditionally used for machine translation, can be technically adapted for targeted monolingual paraphrasing by employing monolingual resources and task-specific features. However, our adaptation of Moses enables the generation of paraphrases that are lexically similar to given hypotheses, although grammatical and semantic fidelity are not consistently preserved.

\paragraph{ Can synthetic paraphrase tables replace translation tables automatically derived from parallel corpora?}
Partially, synthetic paraphrase tables provide partial coverage in the absence of monolingual parallel corpora but introduce substantial noise. Consequently, they cannot fully substitute for large-scale, high-quality monolingual parallel data in paraphrasing tasks.

\paragraph{Can task-specific features enable effective targeted paraphrasing?}
Yes, we introduce a novel feature that guides the decoder toward paraphrases with higher lexical overlap with the evaluated hypothesis. The \textbf{Cove\-red\-Re\-ference\-Feature} successfully enforces lexical targeting during decoding. However, because the feature operates only at the word level, it does not guarantee grammatical correctness or semantic adequacy.
\end{mdframed}
